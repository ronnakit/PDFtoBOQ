## 🤝 1. ปรัชญาการทำงานร่วมกัน (Co-Pilot Principles)

> *"AI คือเครื่องมือทุ่นแรงที่มีความแม่นยำสูงในจุดที่ถนัด แต่ต้องมีมนุษย์กำกับในจุดที่เปราะบาง และต้องใช้โค้ดในการคิดคำนวณตัวเลขเสมอ"*

```
┌─────────────────────────────────────────────────────────────────────────┐
│                           4 เสาหลักของระบบ                              │
├────────────────────┬────────────────────┬───────────────────────────────┤
│ 🟢 AI อ่านแม่น      │ 🟡 คนตรวจซ้ำ        │ 🔴 ห้ามเดา / ⚙️ คิดด้วยโค้ด     │
│ อ่านตาราง Schedule │ นับจุดบนผังกริด    │ ข้อมูลไซต์งานห้ามเดา         │
│ สเปกวัสดุ/ข้อกำหนด  │ ตารางห้อง/แนวตะเข้ │ คำนวณคอนกรีต-เหล็กด้วย Python │
└────────────────────┴────────────────────┴───────────────────────────────┘
```

1. **ไม่ให้ AI คิดเลขเอง (Deterministic Computation):** ตัวเลขปริมาณ, ปริมาตรคอนกรีต, น้ำหนักเหล็ก ต้องคำนวณผ่านสคริปต์ Python 100% เพื่อให้ตรวจสอบย้อนกลับได้ทุกขั้นตอน
2. **ไม่เดาข้อมูลที่ไม่มีในแบบ (Zero Guesswork):** ข้อมูลระดับดินเดิม, ความลึกตอม่อ, สภาพหน้างานจริง ต้องได้จากการสำรวจจริง
3. **โปร่งใสและตรวจสอบได้ (Itemized Transparency):** ตารางปริมาณต้องแสดงแยกรายการย่อยตามที่ถอดจริง (เช่น F1 ใช้ DB12 กี่เส้น) ไม่รวมข้ามหมวดจนมองไม่เห็นที่มา

## 🏛️ 2. สถาปัตยกรรมการแยกชั้นข้อมูล (Data Separation Architecture)

```mermaid
graph TD
    subgraph Global Engine ["⚙️ โค้ดระบบส่วนกลาง (Universal Scripts - ห้ามฝังข้อมูลบ้าน)"]
        G1[new_project.py]
        G2[pdf_inspector.py]
        G3[extract_footing_boq.py]
        G4[extract_beam_boq.py]
        G5[extract_floor_boq.py]
        G6[extract_roof_boq.py]
    end

    subgraph Project Workspace ["📁 ข้อมูลเฉพาะโครงการ (Project Data)"]
        direction TB
        P1["project/<ชื่อโครงการ>/PDF/ (แบบก่อสร้าง)"]
        P2["project/<ชื่อโครงการ>/boq/ (BOQ เทียบ)"]
        P3["project/<ชื่อโครงการ>/cad/ (ไฟล์ CAD)"]
        P4["project/<ชื่อโครงการ>/MD/ (ข้อมูลเฉพาะที่ยืนยันแล้ว)"]
    end

    subgraph MD Storage ["📄 ลิ้นชัก MD เฉพาะโครงการ"]
        M1["ห้องพื้น.md (ตารางห้อง กว้างxยาว ระบบพื้น)"]
        M2["รูปทรงหลังคา.md (ระดับสัน ตำแหน่งเสา ตะเข้)"]
        M3["foundation_data.md (สารบัญ สเปก สัญลักษณ์)"]
    end

    Global Engine -->|อ่านค่าตัวแปร Path & MD| Project Workspace
    P4 --- MD Storage
```

### กฎเหล็กเรื่องการจัดเก็บข้อมูล:
1. **โค้ดส่วนกลาง (Global Core Engine):** สคริปต์คำนวณต้องรับ Path ของโปรเจกต์เป็นตัวแปร (Dynamic Argument) เท่านั้น **ห้ามเขียนชื่อโปรเจกต์หรือฝังขนาดเฉพาะลงในสคริปต์กลางเด็ดขาด**
2. **ข้อมูลเฉพาะโครงการ (Project MD):** ข้อมูลของแบบแต่ละหลัง (ขนาดห้อง, แนวหลังคา, สเปก) **ต้องเก็บไว้ในโฟลเดอร์ `MD/` ของโครงการนั้นๆ เท่านั้น**

## 🔄 4. เวิร์กโฟลว์การทำงานแบบมาตรฐาน (Standard Operating Procedure)

```
[เริ่มต้นโครงการใหม่]
       │
       ▼
[1. รัน new_project.py] ──► ป้อนชื่อโครงการ & ก็อปปี้ไฟล์ PDF/BOQ/CAD เข้าลิ้นชักอัตโนมัติ
       │
       ▼
[2. Stage 0: เตรียมข้อมูล]
       ├── ตรวจประเภท PDF (Vector vs Scan) ด้วย pdf_inspector.py
       ├── สกัดสารบัญ/สัญลักษณ์ ด้วย extract_foundation.py -> บันทึกเป็น MD/foundation_data.md
       └── เช็คความครบของแบบขยาย Schedule (ถ้าขาด ให้หยุดและขอแบบเพิ่มทันที)
       │
       ▼
[3. คนตรวจยืนยันสัญลักษณ์]
       │
       ▼
[4. Stage 1: คำนวณปริมาณ]
       ├── [เส้นทาง A: มีกริด] ──► ฐานราก, เสา, คาน (คนนับจุดผัง + AI อ่านตาราง + Python คำนวณ)
       └── [เส้นทาง B: งานพื้น/หลังคา] ──► คุยยืนยันขนาดห้อง/หลังคา -> เขียนลง MD/ -> Python คำนวณ
       │
       ▼
[5. สรุปผล & ส่วนเสริม] ──► ตารางปริมาณงาน Itemized, รวม Cutting List, เทียบ BOQ
```

## 🛡️ 5. กฎและข้อพึงปฏิบัติของ AI (AI Operational Guardrails)

- ✅ **ก่อนเริ่มทำอะไร:** ต้องตรวจสอบบริบทเสมอว่ากำลังทำงานอยู่กับโปรเจกต์ไหน
- ✅ **เมื่อพบข้อมูลเฉพาะ:** นำไปเขียนลงใน `project/<ชื่อโปรเจกต์>/MD/` ห้ามแก้โค้ดกลาง
- ❌ **ห้ามคิดเลขเองในพรอมต์:** ให้เรียกใช้สคริปต์ Python คำนวณผลลัพธ์
- ❌ **ห้ามข้ามขั้นตอนการยืนยันของมนุษย์:** จุดที่เป็น 🟡 (การนับจุด, ขอบเขตห้อง) ต้องแสดงให้ผู้ใช้ตรวจสอบและยืนยันก่อนเสมอ
