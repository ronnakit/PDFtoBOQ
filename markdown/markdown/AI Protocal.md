# CLAUDE.md

คำแนะนำสำหรับ Claude Code เมื่อทำงานในรีโพนี้

## โครงการนี้คืออะไร

รีโพเอกสาร (documentation-first) สำหรับแพลตฟอร์มถอดแบบ CAD (DWG/DXF) เป็น BOQ อัตโนมัติด้วย AI agent "ไพน้อย" — เป็นโครงการ nested อยู่ในเครือรักบ้าน@CNX (ดู `D:\dev\rakbaan_md\`) แต่เป็น git repo แยกต่างหาก ยังไม่มี remote บน GitHub ยังไม่มีโค้ดจริง มีแต่เอกสารพิมพ์เขียว ดูสารบัญที่ [README.md](./README.md)

## ข้อตกลงในการทำงาน (เหมือนรีโพรักบ้าน)

- **ภาษาที่ใช้สื่อสาร:** ตอบกลับผู้ใช้เป็นภาษาไทยเสมอ โค้ด/path/ศัพท์เทคนิคเป็นภาษาอังกฤษได้ตามปกติ
- **การ commit/push:** สร้าง commit หรือ push ให้เฉพาะเมื่อผู้ใช้ขอเท่านั้น
- **Distinguish decided vs. open:** แยกให้ชัดว่าอะไรตัดสินใจแล้ว (เขียนตรงๆ) กับอะไรยังเปิดอยู่ (ใช้ checklist `- [ ]` หรือ ⚠️ callout) — อย่าเดาคำตอบของคำถามเปิดเอง
- **LOG.md:** บันทึกการตัดสินใจสำคัญที่กระทบหลายไฟล์ไว้ที่ [LOG.md](./LOG.md) เรียงล่าสุด→เก่าสุด ระบุไฟล์ที่แก้ + เหตุผล
- **BACKLOG.md:** รวมรายการคำถาม/งานค้างไว้ที่เดียวใน [BACKLOG.md](./BACKLOG.md) ชี้กลับไปจุดที่คำถามฝังอยู่ในเอกสาร ไม่ copy เนื้อหามาซ้ำ
- **ชื่อโครงการยังไม่ตัดสินใจ** — ใช้ "AI Estimation Platform" เป็น working title เท่านั้น อย่าเสนอชื่อใหม่เองโดยไม่ถาม ส่วนชื่อ AI agent "ไพน้อย (Py-Noi)" ตัดสินใจแล้ว ใช้ได้เลย
- **ตัวเลขการเงิน/ต้นทุนในเอกสารนี้เป็น illustrative ทั้งหมด** จนกว่าจะมีข้อมูลจริงจากการทดสอบ — ห้ามนำไปนำเสนอนักลงทุน/ลูกค้าโดยไม่ตรวจทานก่อน
- **⚠️ แยกแหล่งที่มาของตัวเลขให้ชัดเจนทุกครั้งที่ทำตาราง/รายงานเปรียบเทียบปริมาณ** — ห้ามใช้คำว่า "จากแบบ" เฉยๆ โดยไม่ระบุว่าใครเป็นคนอ่าน ใช้ 3 label นี้แยกคอลัมน์เสมอ (ใส่เท่าที่มีข้อมูลจริง ไม่ต้องมีครบ 3 ทุกครั้ง):
  - **จากแบบ (AI)** = Claude อ่าน/นับ/วัดเองด้วยสายตาจากภาพที่ render ออกมา ตอนนี้ยังเป็นแค่ผู้ช่วยชั่วคราวในเซสชัน ไม่ใช่ผลลัพธ์จากตัวผลิตภัณฑ์จริง
  - **จากแบบ (ไพน้อย)** = ผลลัพธ์จากการรันโค้ด/สคริปต์จริงในโปรเจกต์ (เช่น `pynoi_parser.py`, `pdf_door_label_matcher.py`) — เป็นตัวแทนสิ่งที่ผลิตภัณฑ์จริงทำได้ ณ ตอนนี้เท่านั้น
  - **BOQ** = ตัวเลขอ้างอิงจาก BOQ ที่ตีราคาจริงโดยมนุษย์ (ground truth)
  - **ห้ามเรียกผลลัพธ์จาก Claude ว่า "ไพน้อย"** — จะทำให้เข้าใจผิดว่าโค้ดที่รันซ้ำได้จริงทำได้ระดับนั้นแล้ว ทั้งที่จริงเป็นความสามารถของ Claude เอง (อ่านภาพ+ภาษาไทยได้) ซึ่งยังไม่ถูกแปลงเป็นโค้ดที่ใช้งานจริงได้

## โครงสร้างโฟลเดอร์ต่อโปรเจกต์ (2569-09-01)

โปรเจกต์ทดสอบแต่ละหลัง (แบบบ้านแต่ละหลังของลูกค้า) เก็บแยกโฟลเดอร์ที่ `project/<ชื่อโปรเจกต์>/` — ไม่ปนกัน ไม่ทับกัน:
- `PDF/` — แบบก่อสร้าง PDF ต้นฉบับ
- `boq/` — ไฟล์ BOQ จริงไว้เทียบ ground truth (ถ้ามี)
- `cad/` — ไฟล์ DXF/DWG (ถ้ามี)
- `MD/` — ข้อมูลเฉพาะโปรเจกต์ที่ยืนยันกับเจ้าของโปรเจกต์แล้ว แต่ไม่ใช่ "ผลลัพธ์สุดท้าย" (เช่น `floor_data.md` = ตารางห้อง+พารามิเตอร์พื้น, `roof_geometry.md` = ระดับ/กริด/ชายคาของหลังคา) — สคริปต์คำนวณอ่านจากตรงนี้ ดู `project_md_data.py`
- `claude_boq.md` — ผลลัพธ์ที่ยืนยันแล้ว (single source of truth ของโปรเจกต์นั้น)
- `foundation_data.md` — ผล Stage 0

**หลักการแยกข้อมูล (สำคัญ):** ข้อมูลที่ใช้ร่วมกันได้ทุกโปรเจกต์ (สูตรคำนวณ, ค่าคงที่ทางฟิสิกส์ของวัสดุ เช่น น้ำหนักเหล็ก กก./เมตร) อยู่ในโค้ด (`extract_*.py`) ได้ตามปกติ — แต่ **ข้อมูลที่ยืนยันเฉพาะบ้านหลังนั้น ต้องอยู่ใน `MD/` ของโปรเจกต์นั้นเท่านั้น ห้ามฝังเป็นค่าคงที่ในสคริปต์**

**เรียกใช้ทุกอย่างผ่าน `project/code/python/pynoi.py` ตัวเดียว** (ประตูเดียว หลายคำสั่งข้างใน เช่น `python pynoi.py floor "../../new house"`, `python pynoi.py --help` ดูคำสั่งทั้งหมด) — ไม่ต้องจำชื่อไฟล์ `extract_*.py` แต่ละไฟล์อีกต่อไป

ใช้ `python pynoi.py new-project` (หรือรัน `new_project.py` ตรงๆ) สร้างโฟลเดอร์มาตรฐานนี้ให้อัตโนมัติ (ถามชื่อโปรเจกต์ + path ไฟล์ PDF/BOQ/CAD แล้วก็อปปี้เข้าที่ให้) — สคริปต์คำนวณทุกตัว (`extract_footing_boq.py`, `extract_beam_boq.py`, `extract_floor_boq.py`, `extract_roof_boq.py` ฯลฯ) รับ path โฟลเดอร์โปรเจกต์เป็น argument แล้วใช้กับโปรเจกต์ใหม่ได้ทันที **แต่** `extract_floor_boq.py`/`extract_roof_boq.py` ต้องมีไฟล์ `MD/floor_data.md`/`MD/roof_geometry.md` ของโปรเจกต์นั้นอยู่ก่อน (ดูตัวอย่างรูปแบบที่ `project/new house/MD/`) — โปรเจกต์ใหม่ต้องยืนยันข้อมูลห้อง/รูปทรงหลังคากับเจ้าของโปรเจกต์คนละหลังก่อนเขียนไฟล์นี้เสมอ ไม่ใช่แค่เปลี่ยน path แล้วรันได้เลย
